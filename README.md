# 광운대 음식점 타이쿤 🍔

방향키로 캐릭터를 움직여 식당에 들어가고, 메뉴를 골라 주문하면 잔고가 줄어든다.
플레이어가 노는 동안에도 NPC 손님들은 알아서 식당을 돌아다니며 주문을 넣는다.
가만히 둬도 도시가 살아 있는, 작은 음식점 경제 시뮬레이션이다.

- **유형** &nbsp; 객체지향프로그래밍 수업 팀 프로젝트
- **기술** &nbsp; Java · Swing · MySQL (JDBC)
- **기간** &nbsp; 2024년 5월 (5/3 ~ 5/21, 약 3주)
- **기록** &nbsp; [기획·회의 노션](https://mytype4.notion.site/e176df2ec4494251805125f8d14f5a2e)

---

## 어떻게 돌아가나

```
        [ 맵 화면 ]                      [ 식당 내부 ]
  ┌───────────────────┐            ┌───────────────────┐
  │  ■도전하라식당      │  식당에     │   ▭ 데스크          │
  │            ■빵팡   │  부딪히면 →  │                    │
  │     ▮(나)          │            │      ▮(나)         │
  │  ■미래식당          │  ← 출구로   │   ▭▭▭ 출구         │
  └───────────────────┘   나가면     └───────────────────┘
```

- **맵**: 식당들이 매번 랜덤한 자리에 깔린다. 방향키로 돌아다니다 식당에 닿으면 안으로 들어간다.
- **식당 안**: 데스크에 다가가면 메뉴판이 뜨고, 숫자 키를 누르면 주문 + 결제. 출구로 나가면 다시 맵으로.
- **백그라운드**: NPC 손님 4명이 각자 타이머를 들고 10초마다 아무 식당에나 들어가 주문한다.
- **기록**: 모든 주문은 MySQL에 쌓이고, 나중에 SQL 비슷한 명령으로 조회할 수 있다.

---

## 실행하기

Eclipse 프로젝트(`Test01/`)다. 빌드 도구는 따로 없다.

1. MySQL을 `localhost:3306`에 띄운다 (계정 `root`, 비번 없음 — `OrderDB.java`에서 바꿀 수 있음)
2. MySQL JDBC 드라이버 `.jar`를 클래스패스에 넣는다
3. 셋 중 하나를 실행한다:

| 클래스 | 하는 일 |
|--------|---------|
| `MovingCharacter` | **게임 본편** — 맵을 돌며 직접 주문 |
| `Simulation` | 콘솔에서 NPC 자동 주문만 구동 |
| `Main` | 쌓인 주문을 쿼리로 조회 |

## 코드 한눈에 보기

```
Person (추상)              사람의 공통분모: 이름, 잔고, pay()
 ├─ Customer               식당 방문·주문, 스케줄러로 자동 주문
 │   └─ Me                 내가 조종하는 캐릭터
 └─ Owner                  식당을 열고 메뉴를 등록

SimulationManager (싱글톤) 모든 객체와 DB를 한곳에서 관리
Restaurant · Menu          식당과 메뉴
Order · OrderDB            주문 기록과 MySQL 저장소
MovingCharacter            맵 화면
RestaurantInterior         식당 내부 화면
```

한 줄 요약: **돈을 가진 사람(`Person`)들이 식당(`Restaurant`)에서 메뉴(`Menu`)를
주문(`Order`)하고, 그 전부를 매니저(`SimulationManager`)가 묶어 화면(`Swing`)에 띄운다.**

## 만들면서 부딪힌 것들

가장 기억에 남는 건 **될 때 안 될 때가 반반이던 버그**였다.
프로그램을 켜거나 식당에서 막 나왔을 때, 들어가지도 않은 식당 안 화면이
혼자 떠버리곤 했다. 차라리 항상 안 됐으면 원인이라도 잡았을 텐데,
절반은 멀쩡하고 절반은 고장 나니 도무지 감이 안 잡혀 한참을 헤맸다.
(ChatGPT가 막 나온 초기라 AI한테 물어봐도 영 못 잡아줬다.)

알고 보니 **좌표 계산과 화면 그리기 사이에 순서 보장이 없는 게 문제**였다.
식당과 캐릭터의 좌표가 정해지기 전에 화면이 먼저 그려지면, 모든 게
`(0, 0)`에 겹쳐 버린다. 그 순간 캐릭터가 식당과 닿은 걸로 판정돼
곧바로 식당 안으로 빨려 들어갔던 것이다. 타이밍이 간발의 차이라
어떤 날은 좌표가 먼저 잡혀 멀쩡하고, 어떤 날은 화면이 먼저 떠 고장 났다.
"반반"의 정체는 이 **경쟁 상태(race condition)** 였다.

`initialPositionSet` 플래그를 둬서 **좌표가 다 정해지기 전에는 아예 그리지도,
움직이지도 않게** 막자 버그가 깨끗이 사라졌다. 순서를 보장해 준 것이다.

화면을 맵 ↔ 식당으로 갈아끼울 때 키 입력 상태가 눌린 채로 남아
캐릭터가 혼자 미끄러지는 문제도 있었는데, 화면 전환마다 키 상태를
초기화하고 타이머를 멈췄다 켜는 식으로 잡았다.
커밋 로그에 "문제 해결"이 유난히 많은 건 그래서다.
